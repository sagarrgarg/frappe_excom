Method: two independent read-only sweeps (doctype/lifecycle, roles/permissions) plus mechanical checks I ran
against the live dev copy — 133 whitelisted endpoints parsed with `ast`, every hook target and patch resolved,
doctype JSON vs database columns, and the frontend's method strings vs the Python whitelist.

## Known and accepted, with reasons

- **Two assignment engines** (claim-on-talk and Frappe Assignment Rules) both write `assigned_to`. Deliberate; documented in `lead_sources.md`.
- **Lead/identity link stored twice** (`Lead.omni_identity` + `Omni Identity Link`): readers use one or the other. Non-atomic in theory; `on_lead_created` repairs the common case. Worth unifying behind the gateway.
- **`Excom Thread.account_doctype`** is a Dynamic Link with exactly one possible value. Harmless, historical.
- **Dead fields**: `Omni Identity.ai_profile_summary`, `Excom Thread.priority`, `merge_group_id`, `Excom Source Log.status = Duplicate`.
- **Cascade deletes** (identity/thread) leave `Excom Source Log`, `Excom Visitor Session`, `Excom Broadcast Log/Event`, `Excom Subscriber` pointing at deleted rows.
- **Broadcast outbound counts as a first response** in the SLA clock.
- **Closure state**: the email and web-chat inbound paths reopen a Closed thread without clearing `closure_outcome`, and `archive_thread` writes `Closed` with no outcome.
- **`webchat.create_session`** is a guest endpoint with a rate limit but no origin/IP allowlist, unlike the intake endpoints.
- **Missing indexes** on `Excom Source Log.status/received_at`.
- **Team listings** (`get_all_teams`, `get_team_members`, `search_users`) are visible to any Excom User.

Next pass should take the closure-state unification, the SLA/broadcast rule and the cascade cleanup together — they are one theme: every state transition should go through one function.
